### Reviewed, no defect found

- SQL: every query uses bound parameters. The only interpolated pieces are `UPDATE ... SET ${updates}` built from fixed column names in `users.js` and `api.js`, and table names from the constant `TABLES` list in `backups.js`.
- Sessions: 256-bit random tokens, 30-day expiry checked in SQL on every request, deleted on user delete and on logout.
- Password hashing: PBKDF2-SHA256, 120,000 iterations, per-user salt, `timingSafeEqual`.
- Open bootstrap mode applies only when no API key is set and no users exist. Creating the first user closes it.
- Backup restore: runs in one transaction (a failing restore rolled back completely in the new test), clears sessions, cannot inject sessions (not in `TABLES`), rejects unknown columns, validates app and version.
- `fetchText`: http/https only, no redirects, 15 s timeout, 1 MB cap, no body echo. `yt-dlp` playlist URLs must parse as a `new URL`, so cannot start with `-`.
- `yt-dlp` and `ffmpeg` are always started with `execFile` and an argument array, never a shell string.
- Spotify: token is never logged or returned (`publicConfig` masks the secret); cached token is cleared when credentials change. The settings UI sends `undefined` rather than the masked value, so a masked secret is not written back.
- Secrets in errors: Prowlarr, qBittorrent and webhook error messages include at most 300 characters of the remote response body, not the request. Notification and `GET /settings/*` responses mask keys and webhooks.
- Secret scan of the working tree and all 22 commits (key, token, webhook and private-key patterns, database, `.env`, `.pem` and CSV files): no hits. All commits are by `deadinternetchoir`.

## Changes to behaviour users may notice

- A `user`-role account now gets 403 on backup export/preview and on saving or testing Prowlarr, Spotify, notifications, rTorrent, download-client and library settings.
- A password change signs the user's other sessions out.
- Demoting the last admin returns 400.
- A second Download click for the same track returns the existing job id instead of creating a new job.
- An artist name starting with dots or consisting only of stripped characters gets a different folder (`Unknown Artist` for the latter).
- Without `ffmpeg`, candidates are no longer rejected as static.
